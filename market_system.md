# Market System in Bitcoin

This document outlines the decentralized marketplace functionality, including its data structures, user operations, and data propagation mechanisms, as implemented in this version of the Bitcoin client.

## Market Data Structures

The market system relies on several key data structures defined in `market.h`.

### `CUser`

Represents a user in the reputation/market system. It primarily tracks "atoms," which seem to be units of reputation or interaction.

```cpp
// From market.h
class CUser
{
public:
    vector<unsigned short> vAtomsIn;  // Atoms received and processed
    vector<unsigned short> vAtomsNew; // New atoms received, pending processing for flow-through
    vector<unsigned short> vAtomsOut; // Atoms that this user will propagate outwards
    vector<uint256> vLinksOut;        // Hashes of users this user has linked to (e.g., by reviewing)

    CUser();
    IMPLEMENT_SERIALIZE(...)
    void SetNull();
    uint256 GetHash() const;
    int GetAtomCount() const; // Total of vAtomsIn + vAtomsNew
    void AddAtom(unsigned short nAtom, bool fOrigin); // Logic for adding and managing atom flow
};
```

*   **`vAtomsIn`**: A sorted vector of atom IDs that the user has already incorporated.
*   **`vAtomsNew`**: A vector of newly received atom IDs. These are periodically processed.
*   **`vAtomsOut`**: A vector of atom IDs that this user has chosen to propagate to others they link to.
*   **`vLinksOut`**: A vector of `uint256` hashes, representing other users or entities this user has interacted with or vouched for (e.g., by writing a review for them).
*   **Atom Flow**: The `AddAtom` method implements a flow-through mechanism. New atoms are added to `vAtomsNew`. When `vAtomsNew` reaches `nFlowthroughRate` (defined as 2) or if `vAtomsOut` is empty, an atom from `vAtomsNew` is selected (randomly) to be moved to `vAtomsOut` for propagation, and `vAtomsNew` is merged into `vAtomsIn`. "Origin" atoms (created by this user, or the special atom 0) are handled differently, often directly going into `vAtomsIn` and potentially `vAtomsOut`.

### `CReview`

Represents a review written by one user for another entity (likely a product or another user).

```cpp
// From market.h
class CReview
{
public:
    int nVersion;
    uint256 hashTo;                     // Hash of the entity being reviewed
    map<string, string> mapValue;       // Key-value pairs for review content (e.g., "rating", "comment")
    vector<unsigned char> vchPubKeyFrom; // Public key of the reviewer
    vector<unsigned char> vchSig;        // Signature of the review (GetSigHash() is signed)

    // memory only
    unsigned int nTime; // Time the review was accepted
    int nAtoms;         // (Potentially) atom count of the reviewer at the time of review

    CReview();
    IMPLEMENT_SERIALIZE(...)
    uint256 GetHash() const;      // Hash of the review itself
    uint256 GetSigHash() const;   // Hash of the review data for signing (excludes signature)
    uint256 GetUserHash() const;  // Hash of the reviewer's public key
    bool AcceptReview();          // Validates and processes the review
};
```

*   **`hashTo`**: The target of the review.
*   **`mapValue`**: Stores arbitrary review data, like text comments, ratings, etc.
*   **`vchPubKeyFrom`**: The public key of the user who wrote the review.
*   **`vchSig`**: The cryptographic signature, ensuring the review's authenticity and integrity. It signs the hash generated by `GetSigHash()`.

### `CProduct`

Represents a product or service listing in the marketplace.

```cpp
// From market.h
class CProduct
{
public:
    int nVersion;
    CAddress addr;                        // Contact address for the product/seller
    map<string, string> mapValue;       // General product information (e.g., "title", "description")
    map<string, string> mapDetails;     // More detailed product specifics
    vector<pair<string, string> > vOrderForm; // Defines fields for an order form
    unsigned int nSequence;               // Sequence number for updates
    vector<unsigned char> vchPubKeyFrom;  // Public key of the seller
    vector<unsigned char> vchSig;         // Signature of the product listing

    // disk only
    int nAtoms; // Seller's atom count at the time of listing/last update

    // memory only
    set<unsigned int> setSources; // IPs of nodes from which this product was received

    CProduct();
    IMPLEMENT_SERIALIZE(...)
    uint256 GetHash() const;
    uint256 GetSigHash() const;
    uint256 GetUserHash() const; // Hash of the seller's public key
    bool CheckSignature();
    bool CheckProduct();        // Validates the product summary for network acceptance
};
```

*   **`addr`**: A `CAddress` for contacting the seller.
*   **`mapValue`**: General descriptive fields for the product.
*   **`mapDetails`**: Potentially more extensive details.
*   **`vOrderForm`**: Specifies fields required when a buyer wants to place an order.
*   **`nSequence`**: A sequence number to handle updates to the product listing. Higher numbers supersede lower ones.
*   **`vchPubKeyFrom`**: The seller's public key, used to verify the signature.
*   **`vchSig`**: Cryptographic signature over `GetSigHash()` of the product data.
*   **`nAtoms`**: Stored on disk, likely representing the seller's reputation (atom count) when the product was listed or last updated.
*   **`setSources`**: In-memory set of IPs from which this product data has been received, used for network propagation.

## Market Operations

Users can interact with the market system in several ways, primarily defined by methods in `market.cpp`.

### Creating a Product Listing

Creating a new product listing involves constructing a `CProduct` object, signing it, and then having it accepted by the network.

1.  **Initialization**: The user creates a `CProduct` object, filling in `addr`, `mapValue` (title, description, price, etc.), `mapDetails`, `vOrderForm`, their `vchPubKeyFrom`. `nSequence` would typically start at 0 or a current timestamp.
2.  **Signing**: The user signs the product data (specifically `GetSigHash()`) using their private key, and the resulting signature is stored in `vchSig`.
3.  **Network Submission/Validation**:
    *   The product is then broadcast to the network.
    *   When a node receives a product, `CProduct::CheckProduct()` is called (often for "summary" products, meaning `mapDetails` and `vOrderForm` might be initially empty for a basic listing).
        ```cpp
        // From market.cpp
        bool CProduct::CheckProduct()
        {
            if (!CheckSignature()) // Verifies vchSig against vchPubKeyFrom and GetSigHash()
                return false;

            // Make sure it's a summary product
            if (!mapDetails.empty() || !vOrderForm.empty()) // This check implies full details might be sent separately or after initial listing
                return false;

            // Look up seller's atom count
            CReviewDB reviewdb("r");
            CUser user;
            reviewdb.ReadUser(GetUserHash(), user); // GetUserHash() is Hash(vchPubKeyFrom)
            nAtoms = user.GetAtomCount();
            reviewdb.Close();

            return true;
        }
        ```
    *   If `CheckProduct()` is successful, `AdvertInsert(product)` is called:
        ```cpp
        // From market.cpp
        bool AdvertInsert(const CProduct& product)
        {
            uint256 hash = product.GetHash();
            bool fNew = false;
            bool fUpdated = false;

            CRITICAL_BLOCK(cs_mapProducts)
            {
                // Insert or find existing product
                pair<map<uint256, CProduct>::iterator, bool> item = mapProducts.insert(make_pair(hash, product));
                CProduct* pproduct = &(*(item.first)).second;
                fNew = item.second;

                // Update if newer (higher sequence number)
                if (product.nSequence > pproduct->nSequence)
                {
                    *pproduct = product;
                    fUpdated = true;
                }
            }
            // ... Notify UI ...
            return (fNew || fUpdated);
        }
        ```
    *   `AdvertInsert` adds the product to the node's local `mapProducts` if it's new or an update (higher `nSequence`). This map likely represents the node's view of available products on the network.
    *   The product is then relayed to other peers (details in Atom Propagation / standard message relay).

### Placing an Order

The process for placing an order is not explicitly detailed with a single "PlaceOrder" function in `market.cpp`. However, it can be inferred:
1.  A buyer would find a `CProduct` listing.
2.  The `vOrderForm` in `CProduct` would specify the fields the buyer needs to fill.
3.  The buyer would construct a message (possibly a generic transaction or a specialized "order" message type not fully shown in these snippets) containing the filled order form data and details of the product they wish to purchase.
4.  This order message would be sent to the seller's `CAddress` specified in the `CProduct`.
5.  The existing `submitorder` and `checkorder` message types in `main.cpp` (though not in `market.cpp`) hint at a mechanism where an order is submitted, potentially checked by the recipient, and a reply is sent. These involve `CWalletTx` and might be more related to payment than the market order itself, or they could be combined.

### Leaving a Review

Users can leave reviews for products or other users using the `CReview` structure.

1.  **Creation**: A user creates a `CReview` object, specifying `hashTo` (the hash of the item/user being reviewed), `mapValue` (review content like rating, text), and their `vchPubKeyFrom`.
2.  **Signing**: The user signs the review's `GetSigHash()` and stores it in `vchSig`.
3.  **Submission & Acceptance**: The review is broadcast. When a node receives it, `CReview::AcceptReview()` is called:
    ```cpp
    // From market.cpp
    bool CReview::AcceptReview()
    {
        // Timestamp
        nTime = GetTime(); // Sets current time

        // Check signature
        if (!CKey::Verify(vchPubKeyFrom, GetSigHash(), vchSig))
            return false;

        CReviewDB reviewdb;

        // Add review text to recipient (hashTo)
        vector<CReview> vReviews;
        reviewdb.ReadReviews(hashTo, vReviews); // Read existing reviews for the target
        vReviews.push_back(*this);              // Add the new review
        if (!reviewdb.WriteReviews(hashTo, vReviews)) // Write back the updated list
            return false;

        // Add link from sender (reviewer) to recipient (reviewed entity)
        CUser user; // Reviewer's user object
        uint256 hashFrom = Hash(vchPubKeyFrom.begin(), vchPubKeyFrom.end());
        reviewdb.ReadUser(hashFrom, user);
        user.vLinksOut.push_back(hashTo); // Add the reviewed entity to the reviewer's outgoing links
        if (!reviewdb.WriteUser(hashFrom, user))
            return false;

        reviewdb.Close();

        // Propagate atoms to recipient (the one being reviewed)
        // The reviewer's outgoing atoms (or a zero atom if none) are propagated to the reviewed entity.
        vector<unsigned short> vZeroAtom(1, 0);
        if (!AddAtomsAndPropagate(hashTo, user.vAtomsOut.size() ? user.vAtomsOut : vZeroAtom, false))
            return false;

        return true;
    }
    ```
    *   The signature is verified.
    *   The review is added to a list of reviews associated with `hashTo` in the `reviews.dat` database.
    *   A link is created in the reviewer's `CUser` object, adding `hashTo` to their `vLinksOut`.
    *   Critically, the reviewer's "atoms" (from `user.vAtomsOut`) are propagated to the `hashTo` entity via `AddAtomsAndPropagate`. This is the core of the reputation flow.

## Atom Propagation

"Atoms" appear to be units of reputation or interaction that flow between users in the market system. The propagation mechanism is primarily handled by `AddAtomsAndPropagate` and `CUser::AddAtom`.

```cpp
// From CUser::AddAtom in market.h
void CUser::AddAtom(unsigned short nAtom, bool fOrigin)
{
    // Ignore duplicates
    if (binary_search(vAtomsIn.begin(), vAtomsIn.end(), nAtom) ||
        find(vAtomsNew.begin(), vAtomsNew.end(), nAtom) != vAtomsNew.end())
        return;

    // ... (special handling for atom 0 or fOrigin true) ...
    // if (nAtom == 0 || fOrigin) { ... return; }

    vAtomsNew.push_back(nAtom); // Add to temporary new atoms list

    if (vAtomsNew.size() >= nFlowthroughRate || vAtomsOut.empty()) // nFlowthroughRate = 2
    {
        // Select atom to flow through to vAtomsOut
        vAtomsOut.push_back(vAtomsNew[GetRand(vAtomsNew.size())]); // Pick one randomly from new atoms

        // Merge vAtomsNew into vAtomsIn (processed atoms)
        sort(vAtomsNew.begin(), vAtomsNew.end());
        Union(vAtomsIn, vAtomsNew); // Union also sorts vAtomsIn
        vAtomsNew.clear();
    }
}

// From market.cpp
bool AddAtomsAndPropagate(uint256 hashUserStart, const vector<unsigned short>& vAtoms, bool fOrigin)
{
    CReviewDB reviewdb;
    map<uint256, vector<unsigned short> > pmapPropagate[2]; // Two maps for current and next hop
    pmapPropagate[0][hashUserStart] = vAtoms; // Initialize with starting user and atoms

    for (int side = 0; !pmapPropagate[side].empty(); side = 1 - side) // Ping-pong between maps
    {
        map<uint256, vector<unsigned short> >& mapFrom = pmapPropagate[side];
        map<uint256, vector<unsigned short> >& mapTo = pmapPropagate[1 - side];

        for (map<uint256, vector<unsigned short> >::iterator mi = mapFrom.begin(); mi != mapFrom.end(); ++mi)
        {
            const uint256& hashUser = (*mi).first;
            const vector<unsigned short>& vReceived = (*mi).second;

            // Read user from DB
            CUser user;
            reviewdb.ReadUser(hashUser, user);
            // ... store old atom counts for comparison ...

            // Add received atoms to this user
            foreach(unsigned short nAtom, vReceived)
                user.AddAtom(nAtom, fOrigin); // This applies the flow-through logic
            fOrigin = false; // fOrigin is true only for the very first call

            // ... (check if user's atom state changed) ...

            // Propagate: If user.vAtomsOut was changed by AddAtom,
            // take the newly added atoms in vAtomsOut and add them to mapTo for users linked by user.vLinksOut
            if (user.vAtomsOut.size() > nOut_old_size) // Simplified condition
                foreach(const uint256& linkedHash, user.vLinksOut) // For each user this one links to
                    mapTo[linkedHash].insert(mapTo[linkedHash].end(), user.vAtomsOut.begin() + nOut_old_size, user.vAtomsOut.end());

            // Write user back to DB
            if (!reviewdb.WriteUser(hashUser, user)) return false;
        }
        mapFrom.clear(); // Clear processed users for this hop
    }
    return true;
}
```

**Explanation:**
1.  **`CUser::AddAtom`**: This method is called on a specific user when they receive atoms.
    *   It avoids duplicates.
    *   New, non-origin atoms are added to `vAtomsNew`.
    *   When `vAtomsNew` is full enough (reaches `nFlowthroughRate`) or if `vAtomsOut` is empty, one atom from `vAtomsNew` is randomly selected and moved to `vAtomsOut`. The rest of `vAtomsNew` are then merged into `vAtomsIn`. This creates a "flow-through" effect where not all received atoms are immediately passed on, and the choice of which one passes is somewhat random.
2.  **`AddAtomsAndPropagate`**: This function orchestrates the multi-hop propagation.
    *   It takes a starting user hash (`hashUserStart`) and a set of atoms (`vAtoms`) to give to this user. `fOrigin` is true if these are newly minted atoms at the source of an action (like a review).
    *   It uses two maps, `pmapPropagate[0]` and `pmapPropagate[1]`, to manage the current set of users to process and the next set of users to propagate to.
    *   **Iteration**: It iterates in "hops". In each hop:
        *   For each user in the current `mapFrom`:
            *   It reads the `CUser` object from the database.
            *   It calls `user.AddAtom()` for each received atom. This might change `user.vAtomsOut`.
            *   If `user.vAtomsOut` has new atoms added (meaning an atom flowed through), these new atoms are collected.
            *   For every `linkedHash` in `user.vLinksOut`, these new atoms from `vAtomsOut` are added to `mapTo[linkedHash]`, queuing them for processing in the next hop.
            *   The updated `CUser` object is written back to the database.
        *   The `mapFrom` is cleared, and `mapTo` becomes `mapFrom` for the next iteration.
    *   This continues until no more atoms are propagated to `mapTo` in a given hop (i.e., `pmapPropagate[side]` becomes empty).

This system creates a decentralized way for reputation (atoms) to flow from one user to another based on their interactions (links, like reviews). The propagation is not direct but probabilistic and multi-hop.
